# Diferencias entre Kanban y Scrum

Kanban y Scrum son dos marcos ágiles para organizar el trabajo, pero con enfoques distintos: Scrum trabaja por sprints y Kanban por flujo continuo.

## Tabla comparativa

| Aspecto | Scrum | Kanban |
|---|---|---|
| Cadencia | Sprints de duración fija | Flujo continuo |
| Roles | Product Owner, Scrum Master, Developers | No prescribe roles |
| Ceremonias | Planning, Daily, Review, Retrospective | No prescribe ceremonias |
| Artefactos | Product Backlog, Sprint Backlog, Incremento | Tablero, tarjetas, límites WIP |
| Cambios | Entre sprints | Cuando hay capacidad |
| Límite de trabajo | Implícito (capacidad del sprint) | Explícito (límites WIP) |
| Métricas | Velocidad, burndown | Lead time, cycle time, throughput |
| Ideal para | Entregas iterativas | Trabajo continuo con prioridades cambiantes |

## Similitudes

- Ambos son marcos ágiles.
- Visualizan el trabajo y aportan transparencia.
- Ayudan a detectar cuellos de botella y mejorar continuamente.
- Se pueden combinar (Scrum + tablero Kanban para el sprint).

## Conclusión

Scrum aporta estructura con sprints, roles y ceremonias; Kanban aporta flexibilidad con flujo continuo y límites WIP. No son excluyentes: el equipo elige según su contexto.
